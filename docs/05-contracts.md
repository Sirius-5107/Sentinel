# Domain Contracts

**Document status:** Authoritative — Phase 1 implementation specification.

This document is the canonical contract for every domain model in `sentinel_core`. It is derived from the vision, SDD, architecture, domain model, and all ADRs. No field, relationship, or rule in this document has been invented — every decision traces back to one of those sources.

An engineer implementing Phase 1 must be able to read this document and produce every model without asking a single question. Where genuine ambiguity exists in the source documentation, it is explicitly called out in an **Ambiguity** block rather than silently resolved.

## 1. Reading This Document

### Field Table Columns

| Column | Meaning |
|---|---|
| **Field** | Python attribute name (`snake_case`) |
| **Type** | Python type annotation. `str`, `int`, `UUID`, `datetime`, custom value object, or enum |
| **Required** | Must be supplied at construction time. No default exists. |
| **Nullable** | `Optional[T]` — value may be `None` at rest in the database |
| **Default** | Value assigned when the field is omitted at construction |
| **Validation** | Rules enforced by Pydantic before the object is accepted |

### Type Notation

- `UUID` — `uuid.UUID` from the standard library, version 4.
- `datetime` — always UTC, always timezone-aware (`datetime` with `tzinfo=timezone.utc`).
- `HttpUrl` — Pydantic's `HttpUrl` type; validates scheme is `http` or `https`.
- `PositiveInt` — `int` constrained to `> 0`.
- Custom value objects and enums are defined in [Section 2](#2-value-objects) and [Section 3](#3-enumerations).

### Identity Convention

Every model uses a `UUID` primary key named `id`. UUIDs are generated by the application layer, not the database. This allows objects to be constructed and validated before any database interaction occurs.

### Timestamp Convention

Every model carries two timestamps:

| Field | Meaning |
|---|---|
| `created_at` | Set once at construction. Never updated. |
| `updated_at` | Set at construction. Updated on every mutation. |

Both are UTC-aware `datetime` values. The application layer sets them; the database does not generate them. This ensures consistent behaviour across all environments.

## 2. Value Objects

Value objects are immutable, validated wrappers around primitive types. They carry no identity of their own. They are defined in `sentinel_core/types/` and reused across all models.

---

### 2.1 `ConfidenceScore`

**Purpose:** Represents the system's confidence in a derived value — classification, entity extraction, importance scoring, or sentiment assessment.

**Underlying type:** `float`

**Constraints:**
- Minimum: `0.0` (no confidence)
- Maximum: `1.0` (certainty)
- Precision: stored to 4 decimal places

**Example:** `0.8750`

**Notes:** A score of `0.0` does not mean the derived value is wrong — it means the system has no basis for confidence. A score of `1.0` is reserved for deterministic outcomes (e.g. a manually verified value), not model outputs. Model outputs should never reach `1.0`.

---

### 2.2 `ImportanceScore`

**Purpose:** Quantifies how significant a piece of information is to the platform's coverage mandate — monitoring global markets and surfacing high-signal developments.

**Underlying type:** `float`

**Constraints:**
- Minimum: `0.0`
- Maximum: `10.0`
- Precision: stored to 2 decimal places

**Scoring guidance (non-normative):**

| Range | Interpretation |
|---|---|
| 0.0 – 2.9 | Noise — routine market movement, duplicated coverage |
| 3.0 – 5.9 | Signal — noteworthy development worth tracking |
| 6.0 – 7.9 | High signal — material market event |
| 8.0 – 10.0 | Critical — systemic or macro-level event |

**Ambiguity:** The scoring bands above are guidance for the LLM prompt and documentation. They are not enforced by the model. The implementation must not hardcode these bands as validation rules.

---

### 2.3 `CountryCode`

**Purpose:** ISO 3166-1 alpha-2 country code.

**Underlying type:** `str`

**Constraints:**
- Exactly 2 characters
- Uppercase only (`[A-Z]{2}`)

**Examples:** `"US"`, `"IN"`, `"GB"`, `"JP"`, `"DE"`

**Notes:** Validation rejects codes that do not match the pattern. No lookup against an authoritative list is performed at the model layer — that would introduce a runtime dependency not justified at this phase.

---

### 2.4 `LanguageCode`

**Purpose:** ISO 639-1 two-letter language code.

**Underlying type:** `str`

**Constraints:**
- Exactly 2 characters
- Lowercase only (`[a-z]{2}`)

**Examples:** `"en"`, `"hi"`, `"zh"`, `"ja"`, `"de"`

---

### 2.5 `Ticker`

**Purpose:** Exchange-listed security identifier in the format `EXCHANGE:SYMBOL`.

**Underlying type:** `str`

**Constraints:**
- Pattern: `[A-Z]{1,10}:[A-Z0-9.]{1,10}`
- Uppercase only
- Maximum 21 characters total

**Examples:** `"NYSE:BRK.B"`, `"NSE:RELIANCE"`, `"NASDAQ:AAPL"`, `"LSE:HSBA"`

**Notes:** The colon separator is mandatory. Exchange prefix is required to avoid ambiguity between identically-named tickers on different exchanges.

---

### 2.6 `Url`

**Purpose:** A validated HTTP or HTTPS URL.

**Underlying type:** Pydantic `HttpUrl`

**Constraints:**
- Scheme must be `http` or `https`
- Must include a host

**Notes:** Use Pydantic's `HttpUrl` directly. Do not create a custom wrapper unless additional behaviour is needed.

## 4. Domain Models

---

### 4.1 `Source`

#### Purpose

Represents a single external content provider from which Sentinel ingests articles. A Source is the entry point into the entire pipeline.

#### Description

Sources are configured in `configs/sources.yaml` and registered in the database. The database record is the runtime source of truth — the YAML file is only used during bootstrap or when adding new sources. Every Article must trace back to exactly one Source.

#### Relationships

| Relationship | Cardinality | Description |
|---|---|---|
| `articles` | One-to-many | All articles ingested from this source |

#### Fields

| Field | Type | Required | Nullable | Default | Validation |
|---|---|---|---|---|---|
| `id` | `UUID` | Yes | No | `uuid4()` | Valid UUID v4 |
| `name` | `str` | Yes | No | — | 1–200 characters; must be unique across all Sources |
| `url` | `Url` | Yes | No | — | Valid `http(s)` URL |
| `source_type` | `SourceType` | Yes | No | — | Must be a valid `SourceType` member |
| `status` | `SourceStatus` | No | No | `SourceStatus.ACTIVE` | Must be a valid `SourceStatus` member |
| `region` | `MarketRegion` | Yes | No | — | Must be a valid `MarketRegion` member |
| `asset_class` | `AssetClass` | Yes | No | — | Must be a valid `AssetClass` member |
| `language` | `LanguageCode` | No | No | `"en"` | Valid ISO 639-1 code |
| `weight` | `float` | No | No | `1.0` | `0.1 ≤ weight ≤ 2.0`; controls relative importance during deduplication and scoring |
| `fetch_interval_minutes` | `PositiveInt` | No | No | `60` | `1 ≤ value ≤ 1440` (max once per day) |
| `last_fetched_at` | `datetime` | No | Yes | `None` | UTC; must not be in the future |
| `last_error` | `str` | No | Yes | `None` | Max 2000 characters; most recent fetch error message |
| `consecutive_errors` | `int` | No | No | `0` | `≥ 0`; resets to `0` on successful fetch |
| `created_at` | `datetime` | No | No | `utcnow()` | UTC; immutable after creation |
| `updated_at` | `datetime` | No | No | `utcnow()` | UTC; updated on every mutation |

#### Validation Rules

- `name` must be unique across all `Source` records. Uniqueness is enforced at the database layer with a unique index. The model layer does not enforce this.
- `consecutive_errors` must not be negative.
- When `status` is `ERROR`, `last_error` should be populated. This is a documentation expectation, not a hard model constraint.
- `weight` outside `[0.1, 2.0]` is rejected. A weight of `0.0` would silently suppress all articles from a source — use `status = PAUSED` instead.

#### Example

```python
Source(
    id=UUID("a1b2c3d4-0000-4000-8000-000000000001"),
    name="Reuters Business",
    url="https://feeds.reuters.com/reuters/businessNews",
    source_type=SourceType.RSS,
    status=SourceStatus.ACTIVE,
    region=MarketRegion.GLOBAL,
    asset_class=AssetClass.MACRO,
    language="en",
    weight=1.0,
    fetch_interval_minutes=60,
    last_fetched_at=datetime(2026, 8, 7, 6, 0, 0, tzinfo=timezone.utc),
    last_error=None,
    consecutive_errors=0,
)
```

### 4.2 `Article`

#### Purpose

Represents a single piece of ingested content — a news article, press release, or data item — at any stage of the processing pipeline.

#### Description

An Article is the fundamental unit of information in Sentinel. Everything downstream — scoring, entity extraction, deduplication, synthesis, reporting — operates on Articles. An Article is created at ingestion and evolves through statuses as it moves through the pipeline. Its content is never modified after ingestion; derived fields (importance, sentiment, entities) are added by the processing stage.

#### Relationships

| Relationship | Cardinality | Description |
|---|---|---|
| `source` | Many-to-one | The Source that produced this article |
| `mentioned_companies` | Many-to-many | Companies explicitly or implicitly referenced in the article |
| `mentioned_people` | Many-to-many | People referenced in the article |
| `mentioned_organizations` | Many-to-many | Non-company organizations referenced |
| `themes` | Many-to-many | Investment themes this article contributes signal to |
| `market_events` | Many-to-many | Market events this article is evidence for |
| `report_sections` | Many-to-many | Report sections in which this article was cited |
| `duplicate_of` | Many-to-one (self) | If deduplicated, points to the canonical article |

#### Fields

| Field | Type | Required | Nullable | Default | Validation |
|---|---|---|---|---|---|
| `id` | `UUID` | Yes | No | `uuid4()` | Valid UUID v4 |
| `source_id` | `UUID` | Yes | No | — | Must reference an existing `Source.id` |
| `title` | `str` | Yes | No | — | 1–500 characters |
| `url` | `Url` | Yes | No | — | Valid `http(s)` URL; must be unique across all Articles |
| `content` | `str` | No | Yes | `None` | Full article body; max 100,000 characters. May be `None` when only a summary was available |
| `summary` | `str` | No | Yes | `None` | LLM-generated or author-provided summary; max 2000 characters |
| `published_at` | `datetime` | No | Yes | `None` | UTC; as reported by the source. `None` when the source did not provide a publication date |
| `fetched_at` | `datetime` | Yes | No | `utcnow()` | UTC; when Sentinel retrieved this article |
| `language` | `LanguageCode` | No | No | `"en"` | Inherited from source if not detected per-article |
| `status` | `ArticleStatus` | No | No | `ArticleStatus.INGESTED` | Valid `ArticleStatus` member |
| `asset_class` | `AssetClass` | No | Yes | `None` | Set by the classifier; `None` until processing completes |
| `region` | `MarketRegion` | No | Yes | `None` | Set by the classifier; `None` until processing completes |
| `sector` | `Sector` | No | Yes | `None` | Set by the classifier; `None` until processing completes |
| `sentiment` | `Sentiment` | No | Yes | `None` | Set by the classifier; `None` until processing completes |
| `sentiment_confidence` | `ConfidenceScore` | No | Yes | `None` | Confidence of the sentiment classification |
| `importance_score` | `ImportanceScore` | No | Yes | `None` | Set by the scorer; `None` until scoring completes |
| `importance_confidence` | `ConfidenceScore` | No | Yes | `None` | Confidence of the importance score |
| `content_hash` | `str` | Yes | No | — | SHA-256 hex digest of `title + url`; used for exact deduplication |
| `embedding_id` | `UUID` | No | Yes | `None` | Reference to the pgvector row storing the article's embedding vector. `None` until embedding is generated |
| `duplicate_of_id` | `UUID` | No | Yes | `None` | If `status = DEDUPLICATED`, the `id` of the canonical article |
| `error_message` | `str` | No | Yes | `None` | Set when `status = FAILED`; max 2000 characters |
| `created_at` | `datetime` | No | No | `utcnow()` | UTC; immutable |
| `updated_at` | `datetime` | No | No | `utcnow()` | UTC; updated on every mutation |

#### Validation Rules

- `url` must be unique across all Article records (database unique index).
- `content_hash` must be unique across all Article records (database unique index). On hash collision, the incoming article is treated as an exact duplicate and immediately given `status = DEDUPLICATED`.
- `duplicate_of_id` must be `None` unless `status = DEDUPLICATED`.
- `sentiment_confidence` must be `None` if `sentiment` is `None`, and non-`None` if `sentiment` is non-`None`.
- `importance_confidence` must be `None` if `importance_score` is `None`, and non-`None` if `importance_score` is non-`None`.
- `published_at`, when present, must not be more than 7 days in the future (clock skew tolerance).

#### Ambiguity

The `content` field is nullable because some RSS sources provide only titles and summaries, not full article bodies. It is not yet specified whether the scraping layer should attempt to fetch full content when `content` is `None`. This decision belongs to the collector design (Phase 2) and must be documented as an ADR at that time.

#### Example

```python
Article(
    id=UUID("b2c3d4e5-0000-4000-8000-000000000002"),
    source_id=UUID("a1b2c3d4-0000-4000-8000-000000000001"),
    title="Fed holds rates steady as inflation cools",
    url="https://feeds.reuters.com/article/fed-rates-2026",
    content="The Federal Reserve held interest rates...",
    summary=None,
    published_at=datetime(2026, 8, 7, 14, 30, 0, tzinfo=timezone.utc),
    fetched_at=datetime(2026, 8, 7, 14, 35, 0, tzinfo=timezone.utc),
    language="en",
    status=ArticleStatus.INGESTED,
    asset_class=None,
    region=None,
    sector=None,
    sentiment=None,
    sentiment_confidence=None,
    importance_score=None,
    importance_confidence=None,
    content_hash="e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855",
    embedding_id=None,
    duplicate_of_id=None,
    error_message=None,
)
```

### 4.3 `Company`

#### Purpose

Represents a publicly or privately held company that appears in Sentinel's coverage universe. Companies are knowledge base entities — they persist independently of any single article and accumulate intelligence over time.

#### Description

Companies are extracted from articles by the entity extraction pipeline and resolved against existing records (deduplication by ticker or name normalisation). A Company record is the long-lived home for all intelligence about that business. It links to the articles that mention it, the themes it participates in, and the market events that affect it.

#### Relationships

| Relationship | Cardinality | Description |
|---|---|---|
| `articles` | Many-to-many | Articles that mention this company |
| `themes` | Many-to-many | Investment themes this company is relevant to |
| `market_events` | Many-to-many | Market events involving this company |
| `market` | Many-to-one | The primary market this company is listed on |

#### Fields

| Field | Type | Required | Nullable | Default | Validation |
|---|---|---|---|---|---|
| `id` | `UUID` | Yes | No | `uuid4()` | Valid UUID v4 |
| `name` | `str` | Yes | No | — | 1–300 characters |
| `legal_name` | `str` | No | Yes | `None` | Full legal entity name; max 500 characters |
| `ticker` | `Ticker` | No | Yes | `None` | `EXCHANGE:SYMBOL` format. Unique when non-`None` |
| `isin` | `str` | No | Yes | `None` | ISO 6166 ISIN; 12 alphanumeric characters; unique when non-`None` |
| `country` | `CountryCode` | No | Yes | `None` | Country of incorporation |
| `sector` | `Sector` | No | Yes | `None` | Primary GICS sector |
| `asset_class` | `AssetClass` | No | Yes | `None` | Relevant asset class (`EQUITY`, `PRIVATE_EQUITY`, etc.) |
| `region` | `MarketRegion` | No | Yes | `None` | Primary market region |
| `market_id` | `UUID` | No | Yes | `None` | Foreign key to `Market`; the primary listing venue |
| `description` | `str` | No | Yes | `None` | LLM-synthesised company overview; max 5000 characters |
| `is_verified` | `bool` | No | No | `False` | `True` if the record has been manually reviewed and confirmed |
| `mention_count` | `int` | No | No | `0` | Denormalised count of articles mentioning this company; `≥ 0` |
| `last_mentioned_at` | `datetime` | No | Yes | `None` | UTC; timestamp of the most recent article mention |
| `created_at` | `datetime` | No | No | `utcnow()` | UTC; immutable |
| `updated_at` | `datetime` | No | No | `utcnow()` | UTC |

#### Validation Rules

- `isin` when present must match `[A-Z]{2}[A-Z0-9]{10}` (2-letter country code + 10 alphanumeric).
- `ticker` when present must be unique across all Company records.
- `isin` when present must be unique across all Company records.
- `mention_count` must be `≥ 0`. It is a denormalised counter — consistency with the actual article relationship count is maintained by the application layer, not by a database constraint.

#### Ambiguity

The `name` field is not enforced as unique at the model layer because different companies may share very similar names (e.g. regional subsidiaries). Deduplication during entity extraction uses a combination of `ticker`, `isin`, and fuzzy name matching. The exact resolution strategy is a processing-layer concern (Phase 3) and must not be encoded in this model.

### 4.4 `Person`

#### Purpose

Represents a named individual — executive, policymaker, analyst, or other market-relevant person — who appears in Sentinel's coverage.

#### Description

People are extracted entities, similar to Companies. They are resolved against existing records by name normalisation and context. A Person record accumulates mentions and associated events over time, enabling the knowledge base to track the influence and coverage of key individuals.

#### Relationships

| Relationship | Cardinality | Description |
|---|---|---|
| `articles` | Many-to-many | Articles that mention this person |
| `organizations` | Many-to-many | Organizations this person is associated with |
| `companies` | Many-to-many | Companies this person is associated with (as executive, board member, etc.) |
| `market_events` | Many-to-many | Market events this person is a principal in |

#### Fields

| Field | Type | Required | Nullable | Default | Validation |
|---|---|---|---|---|---|
| `id` | `UUID` | Yes | No | `uuid4()` | Valid UUID v4 |
| `full_name` | `str` | Yes | No | — | 1–200 characters |
| `title` | `str` | No | Yes | `None` | Current role or title; max 200 characters |
| `organization_name` | `str` | No | Yes | `None` | Primary employer or institution; max 300 characters. Denormalised for display; the authoritative link is via the `organizations` relationship |
| `country` | `CountryCode` | No | Yes | `None` | Country of primary residence or operation |
| `description` | `str` | No | Yes | `None` | Brief biography or role summary; max 2000 characters |
| `is_verified` | `bool` | No | No | `False` | `True` if manually reviewed |
| `mention_count` | `int` | No | No | `0` | Denormalised mention count; `≥ 0` |
| `last_mentioned_at` | `datetime` | No | Yes | `None` | UTC |
| `created_at` | `datetime` | No | No | `utcnow()` | UTC; immutable |
| `updated_at` | `datetime` | No | No | `utcnow()` | UTC |

#### Validation Rules

#### Ambiguity

If such identifiers become available through a data provider in a later phase, a new field should be added via an ADR. Do not add speculative identifier fields at this stage.

### 4.8 `MarketEvent`

#### Purpose

Represents a discrete, time-bounded financial or economic development that has or is expected to have a market impact.

#### Description

A MarketEvent is the output of the intelligence layer's synthesis step. It is derived from one or more Articles, but it is not an article — it is a structured interpretation of what those articles collectively describe. Examples: an earnings release, a central bank rate decision, a merger announcement, a sovereign credit downgrade, a geopolitical development with market implications.

MarketEvents are the primary signal objects. They are what the knowledge base tracks over time, and what report sections are built from.

This is the core of ADR-0001 (event-centric data model): all financial developments are modelled as events with typed entities, a severity level, and temporal attributes.

#### Relationships

| Relationship | Cardinality | Description |
|---|---|---|
| `articles` | Many-to-many | Source articles that together constitute the evidence for this event |
| `companies` | Many-to-many | Companies that are principal actors in this event |
| `people` | Many-to-many | People who are principal actors in this event |
| `organizations` | Many-to-many | Organizations involved in this event |
| `themes` | Many-to-many | Themes this event provides signal for |
| `market` | Many-to-one | Market most directly affected (optional) |
| `report_sections` | Many-to-many | Report sections in which this event is cited |

#### Fields

| Field | Type | Required | Nullable | Default | Validation |
|---|---|---|---|---|---|
| `id` | `UUID` | Yes | No | `uuid4()` | Valid UUID v4 |
| `title` | `str` | Yes | No | — | 1–300 characters; a concise, factual description of the event |
| `summary` | `str` | Yes | No | — | 100–2000 characters; synthesised narrative explaining the event and why it matters |
| `asset_class` | `AssetClass` | Yes | No | — | Primary asset class affected |
| `region` | `MarketRegion` | Yes | No | — | Primary geographic region |
| `sector` | `Sector` | No | Yes | `None` | Sector, if event is sector-specific |
| `severity` | `EventSeverity` | Yes | No | — | Impact level |
| `sentiment` | `Sentiment` | Yes | No | — | Market sentiment signal of this event |
| `sentiment_confidence` | `ConfidenceScore` | Yes | No | — | Confidence in the sentiment assignment |
| `importance_score` | `ImportanceScore` | Yes | No | — | Signal importance score |
| `importance_confidence` | `ConfidenceScore` | Yes | No | — | Confidence in the importance score |
| `occurred_at` | `datetime` | Yes | No | — | UTC; when the real-world event occurred or was announced |
| `market_id` | `UUID` | No | Yes | `None` | FK to `Market`; the most directly affected market |
| `embedding_id` | `UUID` | No | Yes | `None` | Reference to pgvector row for semantic search |
| `created_at` | `datetime` | No | No | `utcnow()` | UTC; immutable |
| `updated_at` | `datetime` | No | No | `utcnow()` | UTC |

#### Validation Rules

- `summary` must be at least 100 characters. One-line summaries do not satisfy the platform's "explain why it matters" principle.
- `occurred_at` must not be more than 30 days in the future.
- `sentiment_confidence` must be a valid `ConfidenceScore` (`0.0–1.0`).
- `importance_confidence` must be a valid `ConfidenceScore` (`0.0–1.0`).
- A `MarketEvent` with no associated `articles` (the join table is empty) must not be persisted. At least one source article is required to satisfy the "Evidence First" principle.

#### Ambiguity

The minimum number of source articles required per MarketEvent is specified as "at least one" here. The intelligence layer (Phase 4) may raise this threshold as part of a quality policy. That decision must not be made here — it belongs in the intelligence layer's configuration.

### 4.9 `ReportSection`

#### Purpose

Represents a single named section within a `DailyReport` — for example "Macro", "US Equities", "India", "AI", "Private Credit".

#### Description

A DailyReport is composed of ordered ReportSections. Each section covers one market segment and contains synthesised narrative text supported by citations to MarketEvents and Articles. Sections are the granular unit of report content — they can be individually regenerated, reviewed, or replaced without rebuilding the entire report.

The section names and ordering correspond to Milestone 3's Daily Brief structure:
`Executive Summary → Macro → US Equities → India → AI → Private Credit → Private Equity → M&A → Outlier Events → Watchlist`.

#### Relationships

| Relationship | Cardinality | Description |
|---|---|---|
| `report` | Many-to-one | The DailyReport this section belongs to |

| `theme` | Many-to-one | Theme this section focuses on (optional; only for theme-specific sections) |

#### Fields

| Field | Type | Required | Nullable | Default | Validation |
|---|---|---|---|---|---|
| `id` | `UUID` | Yes | No | `uuid4()` | Valid UUID v4 |
| `report_id` | `UUID` | Yes | No | — | FK to `DailyReport.id` |
| `title` | `str` | Yes | No | — | 1–200 characters; the section heading (e.g. `"US Equities"`) |
| `order` | `int` | Yes | No | — | `≥ 0`; display position within the report; 0 = first |
| `content` | `str` | No | Yes | `None` | Full section narrative; max 20,000 characters. `None` while the section is being generated |
| `theme_id` | `UUID` | No | Yes | `None` | FK to `Theme`; present only for theme-specific sections |

#### Ambiguity

The field is named `word_count` for readability, but it stores the character count of `content` (Python's `len()`), not a true word count by whitespace splitting. This naming ambiguity is preserved here to match the conventional name used in document processing systems. Implementors must use `len(content)` and document this clearly in the model docstring.

### 4.11 `PipelineRun`

#### Purpose

Represents a single end-to-end execution of the Sentinel data pipeline.

#### Description

A PipelineRun is the operational record of one full cycle: collect → process → synthesise → publish. It acts as the audit log and health indicator for the platform. Every Task executed within a run is linked to its PipelineRun. Operators can query PipelineRuns to understand the health, latency, and output of the system over time.

#### Relationships

| Relationship | Cardinality | Description |
|---|---|---|
| `tasks` | One-to-many | All Tasks executed within this run |
| `daily_report` | One-to-one | The DailyReport produced by this run (if any) |

#### Fields

| Field | Type | Required | Nullable | Default | Validation |
|---|---|---|---|---|---|
| `id` | `UUID` | Yes | No | `uuid4()` | Valid UUID v4 |
| `status` | `PipelineStatus` | No | No | `PipelineStatus.PENDING` | Valid `PipelineStatus` member |
| `started_at` | `datetime` | No | Yes | `None` | UTC; set when status transitions to `RUNNING` |
| `completed_at` | `datetime` | No | Yes | `None` | UTC; set when status reaches a terminal state |
| `duration_seconds` | `float` | No | Yes | `None` | `completed_at - started_at` in seconds; computed, not stored separately. `None` until complete |
| `articles_ingested` | `int` | No | No | `0` | Count of articles collected in this run; `≥ 0` |
| `articles_processed` | `int` | No | No | `0` | Count of articles that completed classification; `≥ 0` |
| `articles_deduplicated` | `int` | No | No | `0` | Count of articles identified as duplicates; `≥ 0` |

#### Validation Rules

- `completed_at` must be `None` when `status` is `PENDING` or `RUNNING`.
- `completed_at` must be `≥ started_at` when non-`None`.
- `started_at` must be `None` when `status = PENDING`.
- `duration_seconds` is a computed property: `(completed_at - started_at).total_seconds()`. It must not be stored as a separate database column — it is derived on read. **Implementors: do not add `duration_seconds` to the SQLAlchemy column definition. Implement it as a `@property`.**
- `articles_ingested ≥ articles_processed` (you cannot process more articles than were ingested).
- `trigger` must be one of `"scheduler"`, `"manual"`, `"api"`.

#### Ambiguity

The `trigger` field uses a plain `str` with documented allowed values rather than a dedicated enum. This is intentional — the set of trigger types is small and operationally stable, and a full enum would require a migration to extend. If trigger types proliferate beyond 5, a `TriggerType` enum should be introduced via an ADR.

- `name` convention: use dot-separated namespacing — `"stage.task_name"` (e.g. `"collect.reuters_rss"`, `"process.classify"`, `"publish.notion"`).
